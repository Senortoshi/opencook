**What you and HODL need to settle before this is built**

A fresh address per post is a proposal; the live site doesn't work this way. It runs into rules that are already decided, all of which count by a person's key:
- The boot price counts active contributors by key.
- Free boots are granted per key.
- The fairness weight uses a square root per contributor, which is what stops one person out-earning others by posting more.
- Posting rate limits are per key.

With a new key per post, none of those can tell who is one person. There are two ways to resolve it:

1. **Nobody can link posts, the server included.** This is the strongest protection. The per-person rules would have to become per-post or per-connection rules.
2. **The public can't link posts, but the server can.** The app privately proves to the server which root account a post belongs to. The existing rules keep working, but anons are then only as safe as the operator and that private mapping.

If "protecting all anons" is the point, option 1 is the one that actually delivers it, and it means reopening the fairness formula.

Even then, a fresh address does not hide everything:
- Writing style and timing still give people away.
- If someone later spends coins from several of their post addresses in one transaction, that transaction links those addresses in public. Paid boots have the same problem.

The building block is already in the codebase: the collectibles address is derived from the identity key the same way a per-post address would be (`src/lib/ord-derivation.ts`).

## What the research said

All three threads agreed with each other:
- **The posts are the interface.** No colour and no boxes in the chrome (Ive, Instagram's 2016 redesign, Facebook's "blank canvas").
- **Type and spacing carry the hierarchy.** One accent, and it has to mean "tappable" or "yours".
- **Counts stay quiet.** Small, grey, hidden at zero. Earnings show only in the wallet.
- **Cut what carries no information.** A box round every post, a face for an anon, a subtitle under the logo, animation for show.
- **Twetch:** "non dual randy" is Billy Rose, the co-founder. Their lesson was to borrow a familiar shell, put the novelty in the money, and never ask for confirmation per action.

## What the mock is now

- **Plain text rows on black** with a hairline between them. No bubbles, no faces, no names.
- **HODL's pixel icon**, done as a record, not a face. Each post carries a 4×4 square with four columns: ideas, backed, steady, voice. Tap one and it explains itself; your own is in the wallet.
- **Quiet boot:** grey until you boot it, with the count in grey.
- **Bare header** with no subtitle. Your own posts get a faint amber tint and "you".
- Every flow from before still works.

## What HODL should know about the pixels

- They can't measure honesty. They show a record, and trust is what a reader infers from it.
- A rare pattern is a fingerprint. On a small board the top contributors will still stand out, so the steps may need to be coarser.
- Someone has to add up the record. If nobody can link a person's posts, nobody can total their pixels either. That is the same decision as the per-post addresses.

## Building it on tBSV

The live code is wired to mainnet in about nine fixed places: the chain lookups in `balance`, `tx-hex`, `unspent`, `useBsvPrice.ts` and `wallet.ts`, plus address prefixes in `boot-confirm` and `contribution-list`. I'd build in this order:

1. **A network setting that defaults to mainnet.** This changes no decision and is safe to do first.
2. **Cooks and the side menu** on the existing identity: tags in post text, per-cook feeds and unread counts.
3. **Per-post addresses and the pixel record.** These wait on HODL choosing whether the server can privately link a person's posts or nobody can. That reopens the fairness formula, free boots and boot pricing, so it's his call.
